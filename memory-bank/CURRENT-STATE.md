# iCopy-X ICS Decoder - Current State

## Critical Findings

### ipk_starter.py - THE MISSING PIECE
- **NOT in GitHub repo** (neither lab-401/icopy-x nor Dysonian-Lab/icopy-x)
- **NOT in SD card contents** (boot partition only - uEnv.txt, kernel, dtb, overlays)
- **NOT generated by build script** - had to create from scratch
- **This is why IPKs installed but NOTHING changed** - the swap never happened!

**Boot chain:** `ipk_starter.py → app.py → main.main() → application.startApp()`

**Swap mechanism:**
1. Installer moves files to `/home/pi/ipk_app_new`
2. On next boot, `ipk_starter.py` swaps `ipk_app_new` → `ipk_app_main`
3. Then launches `app.py`

**Source:** Comments in `src/app.py`, `src/main/install.py`, `src/middleware/update.py` all reference `ipk_starter.py` but it didn't exist.

### SD Card Layout (from boot.cmd)
- `root=/dev/mmcblk0p2` (rootfs2) - Application environment, app runs from `/home/pi/ipk_app_main/`
- `data=/dev/mmcblk0p3` (data partition) - 11GB, mounted at `/mnt/upan/`, exposed as USB mass storage in PC Mode
- **PC Mode drops IPKs into `/mnt/upan/` (data partition)**

### Install Path
- Correct: `/home/pi/` (on rootfs2)
- Wrong: `/mnt/sdcard/root2/root/home/pi/` (QEMU host path)

### Plugin Format (CORRECT)
- Class takes `host` parameter (NOT `bundle`)
- Methods return dicts with `status` key
- Uses `self.host.set_var()`, `self.host.pm3_command()`, etc.
- Does NOT extend BaseActivity
- Requires `ui.json` for UI definition

### Em Dash Bug
- Bytes `0xe2 0x80 94` in Python files cause import crash → black screen brick
- Replace with ASCII hyphen
